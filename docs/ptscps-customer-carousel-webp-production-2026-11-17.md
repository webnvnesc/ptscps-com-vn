# PTSCPS - Customer carousel WebP production checkpoint (2026-11-17)

## Scope and success
User asked to deliver WebP for Elementor customer/partner logo carousel. Audited selector `.elementor-element-1be3f74` on live homepage, 21 mobile / 29 desktop image nodes (19 unique URL images). Existing automatic WebP upload mechanism handles future WordPress uploads, but did **not** backfill historic customer logo files.

- Read-only inventory: [run #44094770705](https://github.com/webnvnesc/ptscps-com-vn/actions/runs/44094770705). All 19 unique logo URLs are JPG or PNG inside `wp-content/uploads`; **0/19** previously returned WebP to an Accept: image/webp client. Browser loaded all images and had no JS errors.
- Production one-time backfill: [run #44095072369](https://github.com/webnvnesc/ptscps-com-vn/actions/runs/44095072369), **SUCCESS**, rollback skipped. 19/19 images converted, each sidecar smaller by at least 4% than source; **38/38** HTTP WebP/fallback checks passed across mobile and desktop.
- Original cumulative bytes **279,362**; WebP sidecar cumulative bytes **87,364**; reduction **68.7%** or **191,998 bytes** across 19 unique images (not an actual page-level transfer saving; carousel clones and lazy loading vary with viewport).
- Both mobile and desktop logo carousel dimensions, image loading and layout regression QA passed `LOGO_DIMS_QA_SUCCESS`. No image URLs or stored Elementor widget content changed; originals untouched; existing upload-wide .htaccess WebP routing serves the sidecars at unchanged JPG/PNG URLs, with JPG/PNG fallback by Accept header.
- Verified sidecars through both web requests: all original URLs respond `image/webp` with WebP Accept and their native `image/png` or `image/jpeg` without WebP Accept.

## Source / rollback
- Source inventory script: `scripts/ptscps-customer-webp-readonly.cjs`.
- One-time FTPS backfill (Pillow WebP quality 82): `scripts/ptscps-customer-webp-backfill.py`. It checks exact audited source file lengths, file path allowlist, correct image dimensions, 4% minimum savings, safe staging/rename and checksum; never overwrites a preexisting sidecar.
- QA: `scripts/ptscps-customer-webp-verify.cjs` plus existing `scripts/ptscps-customer-dims-production-qa.cjs`.
- Workflow: `.github/workflows/ptscps-customer-webp-backfill.yml`, archives state (sidecar paths and hashes), response evidence, and layout QA. Rollback triggers on failure and deletes only sidecars generated by the job when hashes still match. Do not trigger historic fixed-banner rollback, which serves a different purpose.
- Existing Media Library, URL and Elementor edit flows remain unchanged. Future WP-upload JPG/PNG WebP conversion uses the separate installed `ptscps-webp-autogen.php`; this one-time backfill does not establish that end-to-end user upload action was independently exercised.
