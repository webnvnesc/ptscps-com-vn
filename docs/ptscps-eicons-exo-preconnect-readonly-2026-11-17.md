# PTSCPS — Read-only verification of eicons, tielabs-fonticon, Exo preload and Google preconnects (2026-11-17)

User asked to **check feasibility**, not implement modifications:
- 1c: font-display:swap on eicons and tielabs-fonticon; dequeue eicons if unused (claim 108 KB WOFF2 plus 4.6 KB CSS); preload one Exo WOFF2 in first viewport; inspect carousel arrows.
- 1d: remove preconnects to fonts.googleapis.com and fonts.gstatic.com.

Read-only production Chromium audit: [run #44088417139](https://github.com/webnvnesc/ptscps-com-vn/actions/runs/44088417139), 6/6 valid page/device combinations (mobile and desktop homepage, /lien-he, /dich-vu); targeted arrow inspection [run #44089243369](https://github.com/webnvnesc/ptscps-com-vn/actions/runs/44089243369), 2/2 valid, **no production changes**.

## Findings
1. **eicons is used in the homepage customer carousel.** Verified exact DOM:
`<i aria-hidden="true" class="eicon-chevron-left"></i>` with `::before{font-family:eicons;content:"\\e87e"}` (in DOM logged as a private-use Unicode glyph), and `<i class="eicon-chevron-right"></i>` similarly. Both are visible on mobile and desktop. Therefore globally dequeuing eicons without an SVG or CSS replacement **breaks both carousel controls**. Other pages checked (/lien-he and /dich-vu) contain zero eicon DOM usages but still enqueue `/wp-content/plugins/elementor/assets/lib/eicons/css/elementor-icons.min.css?ver=5.53.0`. Real homepage also downloads `/wp-content/plugins/elementor/assets/lib/eicons/fonts/eicons.woff2?5.53.0`. eicons CSS response had 22,258 bytes (uncompressed CSS response in audit). The asserted 4.6 KB CSS and 108 KB WOFF2 byte savings have **not been verified**; gzip/brotli transfer may be less than file size.
2. `tielabs-fonticon.woff2` is loaded in all six page/device cases; browser reports the actual family name as **`tiefonticon`** (not tielabs-fonticon). It is a Jannah theme resource, not proven unused merely because our eicons-oriented CSS computed-style scanner found no `tielabs-fonticon` family literal. Need map real header/nav/social pseudo-elements before any font-display or removal.
3. Local Exo direct CSS exists, `/wp-content/uploads/ptscps-exo-fonts/exo-direct-v1.css`, size 5,445 bytes; 15 `@font-face` records across italic 400/700, normal 400/500/700 and multiple Unicode subsets, **all already have `font-display:swap`**. The existing `deploy/ptscps-exo-css-direct.php` plugin loads this CSS directly, replaces old Jannah webfont.js bootstrap, and uses a body class to activate Exo styling. One-size-fits-all hard-coded preload of a WOFF2 is not safe: choose the actual Exo normal regular font face/subset used in the above-the-fold Vietnamese text and preload only if a controlled A/B confirms improvement, with the right crossorigin/type and no duplicate resources. Exo family is not limited to one face; some woff2 filenames in distinct @font-face records repeat across weights.
4. Both `<link rel=preconnect>` to Google Fonts domains still exist on all six pages, while **no `fonts.googleapis.com` or `fonts.gstatic.com` resource requests were observed** in these successful production Chromium loads. Exo is served from PTSCPS local URL; therefore the two preconnect hints appear redundant and could be removed with minimal risk, scoped to the user-facing WP HTML, preserving admin/editor and not removing arbitrary plugin preconnects.
5. Recommendation order: remove only two redundant Google preconnect hints in a reversible MU or hook after DOM source identification (no broad regex), QA all template pages; consider conditional eicons dequeuing ONLY on verified pages without elements using it, or replace two carousel arrow glyphs with robust SVG then conduct mobile CSS/JS/CLS A/B. Never remove eicons globally before replacing those icons. Font-display swap for decorative icon fonts is low-priority and may create a short tofu/blank glyph flash; verify theme CSS and computed font before action. Exo preload is optional and should be tested, since wrong subset can waste bandwidth and degrade FCP.
