## Findings
- 31 linked stylesheets and 43 covered stylesheets (including inline/dynamic) on mobile homepage.
- First view typography body/header/menu/intro is Exo; several Roboto and Roboto Slab CSS files are loaded.
- CSS Coverage used ranges are **not** a proof that a stylesheet is unnecessary: CSS may be needed for other pages, viewport sizes, interactions and below-fold content.
- Simulated mobile network/CPU FCP in new browser varies significantly with TTFB, so individual measurements must not be credited as causal improvements without repeated stable A/B.
- Prior browser-only tests show:
  - Deferring jQuery by itself causes `jQuery is not defined` errors.
  - Async loading `sr7.css` raises CLS from ~0.009 to ~0.184, undoing a production CLS fix.
  - Async loading Roboto + Roboto Slab caused network errors and fallback typography in one run, not safe to ship.
  - Deferring Jannah `single.min.css` caused mobile CLS ~0.031 compared to baseline ~0.009.
  - Deferring `widgets.min.css` or dark lightbox skin alone preserved CLS but did **not** demonstrate a repeatable FCP improvement, with measured FCP minus TTFB higher than baseline.
- Target Lighthouse FCP <1.8s, but cannot promise this without changing critical-path design or testing.

## Critical CSS extraction / browser A/B (2026-11-16)

- Script: [scripts/critical-css-probe.cjs](../scripts/critical-css-probe.cjs)
- Workflow: [critical CSS run #43811784176](https://github.com/webnvnesc/ptscps-com-vn/actions/runs/43811784176)
- Source: Chrome CSS Coverage measured in mobile viewport width 412; selectors were extracted via PostCSS and injected into the HTML **only in Playwright**. Browser-only overrides deferred corresponding original stylesheets via `media=print` + onload restore. Production was unchanged.
- Approximate inline CSS sizes:
  - `style.min.css`: 134,534 B original -> 6,159 B extracted.
  - `base.min.css`: 40,708 B -> 9,485 B.
  - `widgets.min.css`: 46,691 B -> 452 B.
  - `helpers.min.css`: 33,666 B -> 3,437 B.
  - `elementor/frontend.min.css`: 54,666 B -> 4,960 B.
- Browser measurements (simulated 4x CPU / ~210KiB/s, cold sessions, FCP and TTFB milliseconds):
  | Viewport | Variant | FCP | TTFB | FCP-TTFB | CLS |
  |---|---|---:|---:|---:|---:|
  | 412 | baseline before | 2360 | 828 | 1532 | 0.00912 |
  | 412 | inline Jannah style | 3040 | 1281 | 1759 | 0.00912 |
  | 412 | inline style + base | 2720 | 1045 | 1675 | 0.00912 |
  | 412 | inline style + widgets | 2660 | 1024 | 1636 | 0.00912 |
  | 412 | inline style + base + helpers + widgets | 2844 | 1222 | 1622 | 0.00912 |
  | 412 | inline style + base + Elementor frontend | 4396 | 2230 | 2166 | 0.00912 |
  | 412 | baseline after | 3928 | 834 | 3094 | 0.00903 |
  | 375 | baseline before | 3768 | 834 | 2934 | 0.000084 |
  | 375 | inline Jannah style | 3692 | 1297 | 2395 | 0.000084 |
  | 375 | inline style + base | 3476 | 1229 | 2247 | 0.000084 |
  | 375 | baseline after | 3716 | 837 | 2879 | 0.000084 |
- DOM geometry: header, slider height and intro Y were stable across scenarios. Script and interaction coverage limited; visual screenshots archived with the run.
- **Decision:** Not safe to deploy these changes on production because improvements are inconsistent across tests/viewport, and the CSS extracted from a single moment/viewport is not guaranteed to preserve builders, animation, menus, galleries and responsive states.
- To retry, create a longer repeatable paired A/B benchmark with full page screenshot and user interaction regression checks, cover desktop and authenticated Elementor editor, and only apply a highly localized reversible change after repeatable significant gains.
