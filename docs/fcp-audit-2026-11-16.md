## Findings
- 31 linked stylesheets and 43 covered stylesheets (including inline/dynamic) on mobile homepage.
- First view typography body/header/menu/intro is Exo; several Roboto and Roboto Slab CSS files are loaded.
- CSS Coverage used ranges are **not** a proof that a stylesheet is unnecessary: CSS may be needed for other pages, viewport sizes, interactions and below-fold content.
- Simulated mobile network/CPU FCP in new browser varies significantly with TTFB, so individual measurements must not be credited as causal improvements without repeated stable A/B.
- Prior browser-only tests show:
  - Deferring jQuery by itself causes `jQuery is not defined` errors.
  - Async loading `sr7.css` raises CLS from ~0.009 to ~0.184, undoing a production CLS fix.
  - Async loading Roboto + Roboto Slab caused network errors and fallback typography in one run, not safe to ship.
  - Deferring Jannah `single.min.css` caused mobile CLS ~0.031 compared to baseline ~0.009.
  - Deferring `widgets.min.css` or dark lightbox skin alone preserved CLS but did **not** demonstrate a repeatable FCP improvement, with measured FCP minus TTFB higher than baseline.
- Target Lighthouse FCP <1.8s, but cannot promise this without changing critical-path design or testing.

- Mobile A/B (2 paired cycles, per page): no variant consistently improved FCP-minus-TTFB across all three page types. Mobile CLS stayed ~0.0091 for homepage, but this does not certify responsive/editor compatibility.
- Desktop A/B: removing dark skin and/or alternate block heading CSS on homepage produced **CLS ~0.131**, compared with baseline ~0.00094; do not deploy. Jannah-slider-only removal did not consistently improve FCP on homepage, news category or service detail (paired gaps vary in sign); it saved only 769 compressed bytes.
- The combined three-feature candidate had lower FCP in two desktop homepage samples but also CLS ~0.131; **reject**. This is an example why FCP-only selection is unsafe.
- Specific desktop news-category FCP was highly variable (two-cycle samples), and one simulated case reached 13.46s; treat as a network/server variability signal rather than an effect uniquely attributable to CSS.
- **Decision:** reject all four CSS-removal production candidates. Preserve existing theme, parent CSS, Elementor and Slider Revolution. Investigate other sources of variability (HTML TTFB, critical JavaScript/network competition, fonts and third-party assets) before more CSS surgery. No production changes or FTP asset staging occurred.
